## Введение

На прошлой лекции мы с вами говорили про системы контроля версий, а именно про Git. Он упрощает разработку приложений, а сегодня мы приступим к самой разработке. Давайте вспомним, что мы планируем сделать.

Мы будем делать ИИ-агента, который сможет управлять задачами. Давайте назовём его **Task Agent**. В конечном итоге это будет выглядеть примерно так:


Прежде чем подключать большую языковую модель (LLM), поговорим про Python и среду разработки. За эту лекцию мы реализуем четыре основные команды:
- `add` — добавить задачу;
- `list` — вывести список задач;
- `done` — отметить задачу выполненной;
- `exit` — завершить приложение.

## Среда разработки и IDE

Когда мы говорим про программирование, чаще всего подразумеваем написание кода. Иными словами, мы пишем текст по правилам языка, а затем передаём его программе, которая подготовит код к запуску или выполнит его.

Go, C и C++ обычно компилируют в машинный код заранее. Python, JavaScript и Bash часто называют интерпретируемыми языками. Способ выполнения зависит от реализации. Например, CPython компилирует код Python в байт-код и выполняет его в своей виртуальной машине.

Все примеры курса будут на Python. Давайте откроем любой текстовый редактор, напишем `print("Это TaskAgent!")` и сохраним файл как `task_agent.py`. Теперь его нужно запустить.

Если бы мы писали на Go, то могли бы передать файл `main.go` компилятору командой `go build main.go` и получить исполняемый файл, например `main.exe` на Windows.

Для Python сначала проверим, доступен ли интерпретатор. В Windows можно выполнить `python --version` в PowerShell. При необходимости установите [Python с официального сайта](https://www.python.org/downloads/). В Linux и macOS проверьте `python3 --version` и при необходимости установите Python 3. Из каталога с файлом запустите `python task_agent.py` (или `python3 task_agent.py`, если так называется ваша команда). В терминале появится `Это TaskAgent!`. Дальше в примерах я буду писать `python`.

Можно запустить Python и без имени файла. Откроется интерактивный режим, в котором можно вводить выражения и команды и сразу видеть результат.

Мы вполне можем продолжить писать приложение в условном Блокноте, но для этого уже придумали более удобные программы. IDE (Integrated Development Environment), или интегрированная среда разработки, объединяет инструменты для написания, запуска и отладки кода. Вот несколько примеров:

## Python и виртуальное окружение

Сейчас поговорим про библиотеки, зависимости и виртуальные окружения. Для первого скрипта всё это может показаться лишним, но дальше нам пригодится.

Рано или поздно нам понадобится подключить код из других модулей. Модуль — единица кода, например файл `.py`, который можно импортировать. Пакет позволяет объединять модули под общим именем. Для импорта используется инструкция `import`. Давайте дополним вывод случайным числом. В стандартной библиотеке Python для этого есть модуль `random`.

```python
# Импортируем модуль random
import random

print("Это TaskAgent!")

# Вызываем функцию randint, которая генерирует случайное целое число
# от 0 до 10 включительно
print(random.randint(0, 10))
```

Можно использовать и сторонние пакеты. Их пишут отдельные разработчики, сообщества и компании. Для установки таких пакетов обычно используют `pip`, который по умолчанию ищет их в каталоге PyPI. Например, для установки пакета `rich`, который умеет выводить цветной текст, служит команда:

```bash
python -m pip install rich
```

Вот как будет выглядеть цветной вывод. Установим пакет чуть ниже, после подготовки виртуального окружения:

```python
# Импортируем функцию print из пакета rich.
# В этом модуле имя print теперь ссылается на функцию из rich.
from rich import print

print("Это [bold red]TaskAgent![/bold red]")
```

В выводе `pip` можно увидеть версию установленного пакета. В моём примере это `rich` версии `15.0.0`.

Есть разные способы нумерации версий. Один из них — семантическое версионирование (SemVer). Для стабильного публичного интерфейса в нём действуют такие правила:

- Мажорный номер (`MAJOR`) повышают при несовместимых изменениях публичного интерфейса.
- Минорный номер (`MINOR`) повышают, когда добавляют функциональность с сохранением обратной совместимости.
- Номер исправления (`PATCH`) повышают, когда исправляют ошибки с сохранением обратной совместимости.

Представьте, что старому приложению нужен `rich` версии `14`, а новому — версии `15`. Если оба используют одно окружение Python, обновление пакета для нового приложения может сломать старое. Вот бы можно было держать отдельный набор пакетов для каждого проекта. Для этого в Python есть модуль `venv`.

Давайте создадим виртуальное окружение для нашего проекта. Есть два варианта:
- `python -m venv .venv`
- В палитре команд VS Code выбрать `Python: Create Environment`, затем `Venv`. В интерфейсе выбора интерпретатора эта команда может называться `Create Virtual Environment`
  ![Pasted image 20261008165853](files/Pasted%20image%2020261008165853.png)

Появится каталог `.venv` с отдельным каталогом для установленных пакетов, вспомогательными скриптами и копией или ссылкой на интерпретатор. Структура зависит от ОС.
![Pasted image 20261008170300](files/Pasted%20image%2020261008170300.png)

В Bash или Zsh на Linux и macOS окружение можно активировать так:

```bash
source .venv/bin/activate
```

В PowerShell на Windows:

```powershell
.\.venv\Scripts\Activate.ps1
```

После активации в приглашении терминала обычно появляется `(.venv)`:
```
(.venv) user@pc:~/project$
```

Активация добавляет каталог команд окружения в начало `PATH`. Поэтому `python` в этом терминале запускает интерпретатор окружения. Теперь выполним `python -m pip install rich`, вставим пример с цветным выводом в `task_agent.py` и запустим его. Если PowerShell блокирует скрипт активации, можно обратиться к интерпретатору напрямую командой `.\.venv\Scripts\python.exe -m pip install rich` и так же запустить скрипт.

Каталог `.venv/` добавим в `.gitignore`. Каждый сможет создать своё окружение по конфигурации проекта.

В `.vscode` VS Code хранит настройки рабочего каталога. Личные настройки можно исключить из Git, а общие настройки проекта можно хранить в репозитории.

Теперь представьте, что вы говорите своей подруге Маше: «Маша, проверь, пожалуйста, мою программу». Маша соглашается, клонирует репозиторий, запускает программу, а там:

```text

  File "task_agent.py", line 3, in <module>

ModuleNotFoundError: No module named 'rich'
```

Ага, у Маши нет пакета `rich`. Можно попросить её установить его, но при обычной установке версия может оказаться другой. Пока пакет один, о нужной версии легко договориться. А если зависимостей сто или двести? Давайте запишем требования к ним в проекте.

Один из вариантов — файл `requirements.txt`. Давайте создадим его:
```
rich==15.0.0

```

Здесь мы указали точную версию `rich`. Можно задать и диапазон допустимых версий:

|Оператор|Значение|Пример|
|---|---|---|
|`==`|Точная версия|`requests==2.32.5`|
|`>=`|Не ниже указанной|`requests>=2.30`|
|`<=`|Не выше указанной|`requests<=2.32`|
|`>`|Строго выше|`requests>2.30`|
|`<`|Строго ниже|`requests<3.0`|
|`!=`|Исключить версию|`requests!=2.32.0`|
|`~=`|Совместимый диапазон|`requests~=2.32` допускает версии `>=2.32` в серии `2.*`|
|`===`|Произвольное точное совпадение строки версии|`package===1.0-custom`|

Файл `requirements.txt` можно хранить в Git. Тогда Маше достаточно создать виртуальное окружение и выполнить в нём `python -m pip install -r requirements.txt`.

Теперь попробуем другой вариант. `uv` — менеджер проектов, зависимостей и версий Python от Astral, разработчиков Ruff. Его нужно [установить отдельно](https://docs.astral.sh/uv/getting-started/installation/). Проверьте установку командой `uv --version`.

Сохраним предыдущий этап в Git. Если окружение активировано, выполним `deactivate`. В корне репозитория запустим `uv init --package --name it-taskagent`. Эта команда создаёт конфигурацию и структуру устанавливаемого приложения. Существующий `README.md` пригодится и дальше. После добавления `rich` в конфигурацию проекта демонстрационный `requirements.txt` можно убрать.

Исходный код окажется в каталоге `src/it_taskagent/`. Такая структура называется `src-layout`. Она отделяет исходный код от остальных файлов проекта. Для небольшого скрипта можно выбрать `--no-package`, но нам пригодится отдельный пакет.

Файл `__init__.py` обозначает каталог как обычный пакет Python. При первом импорте пакета в процессе Python выполняет этот файл. В нём можно разместить код инициализации.

В шаблоне приложения `uv` создаёт функцию `main` примерно такого вида:

```python
def main() -> None:
    print("Hello from it-taskagent!")

```

Файл `.python-version` задаёт предпочтительную версию Python для проекта. В `pyproject.toml` описаны метаданные проекта, требования к Python, зависимости и команда запуска в разделе `[project.scripts]`.

Из корня проекта выполним `uv run it-taskagent`. `uv` подготовит окружение и запустит команду из `[project.scripts]`. Давайте раскрасим приветствие в `src/it_taskagent/__init__.py`:

```python
from rich import print

def main() -> None:
    print("Hello from [bold red]it-taskagent![/bold red]")

```

Для этого кода нужен `rich`. Добавим зависимость командой `uv add rich`. Она обновит `pyproject.toml`, создаст или обновит `uv.lock` и по умолчанию синхронизирует окружение. В `[project]` появится запись примерно такого вида:

```toml
dependencies = [
    "rich>=15.0.0",
]
```

Для удаления зависимости есть `uv remove`, например `uv remove rich`. Файл `uv.lock` фиксирует разрешённые версии зависимостей, включая зависимости самих пакетов. Его хранят в Git вместе с `pyproject.toml`. При установке `uv` выбирает из lock-файла варианты, подходящие для платформы и версии Python.

Посмотреть дерево зависимостей проекта можно командой `uv tree`. Версии и состав дерева могут отличаться:

```text
$ uv tree
Resolved 5 packages in 1ms
it-taskagent v0.1.0
└── rich v15.0.0
    ├── markdown-it-py v4.2.0
    │   └── mdurl v0.1.2
    └── pygments v2.21.0
```

Команда `uv lock` создаёт или актуализирует lock-файл. Чтобы запросить обновление до более новых допустимых версий, можно использовать `uv lock --upgrade`.

Логические операторы (logical operators):

- `and` — логическое И

## Хранение и обработка задач

Пока приложение умеет распознавать команды. Теперь надо где-то хранить задачи. Возьмём встроенный тип `list`, то есть список. Задачи будут жить в памяти до завершения программы.

Создадим пустой список в `main` перед циклом:

```python
tasks = []
```

В CPython список устроен как динамический массив. Если `n` — число элементов, то `O(1)` означает, что время операции не растёт вместе с размером списка, а `O(n)` — что оно может расти пропорционально размеру.

- Доступ по индексу занимает `O(1)`.
- Добавление в конец через `append()` занимает `O(1)` в расчёте на одну операцию в серии добавлений. Отдельное добавление при расширении массива может занять `O(n)`.
- Вставка в начало занимает `O(n)`, потому что остальные элементы сдвигаются.

Для обращения к элементу списка по индексу используют квадратные скобки, например `tasks[0]`. Индексация начинается с нуля.
Для добавления в конец списка используется метод `append()`. Заменим ветку `add` в цикле:

```python
if command == "add":
    title = input("Enter task title: ")
    tasks.append(title)
```

Для команды `list` нужно перебрать все элементы списка. Можно использовать `while`, но в Python для перебора элементов есть цикл `for`:

```python
elif command == "list":
    for task in tasks:
        print(task)
```

На каждой итерации имя `task` связывается со следующим элементом списка `tasks`.

Чтобы добавить нумерацию, используем `enumerate(tasks)`. Он возвращает итератор, который по очереди выдаёт пары `(индекс, элемент)`, начиная с нуля. Каждая пара — кортеж (`tuple`). Кортеж похож на список, но заменить его элементы или изменить длину нельзя.

```python
elif command == "list":
    for i, task in enumerate(tasks):
        print(i, task)
```

## Функции и декомпозиция

Наша маленькая программа становится всё больше, и читать её уже сложнее. Давайте обсудим декомпозицию — разбиение программы на части. Подходов много, и разработчики до сих пор спорят, как лучше. Я бы придерживался таких ориентиров:
- Желательно чтобы функция умещалась на экран монитора
- По возможности избегать неожиданных побочных эффектов. Если функция называется «Сложить два числа», от неё ждёшь результата сложения. А от `add_task` мы как раз ждём изменения списка задач.
- Желательно, чтобы функция выполняла одно действие
- Желательно, разделять функциональность на определенные смысловые блоки (доменные области), разделенные модулями

В нашем случае вынесем операции с задачами и вывод справки в отдельные функции. Цикл чтения команд пока оставим в `main`:

```python

def add_task(tasks: list, title: str) -> None:
    tasks.append({
        "title": title,
        "done": False
    })

def list_tasks(tasks: list) -> str:
    output = ""
    for i, task in enumerate(tasks):
        output += f"{i}. [{'X' if task['done'] else ' '}] {task['title']}\n"
    return output

def mark_task_done(tasks: list, index: int) -> None:
    tasks[index]["done"] = True

def print_help() -> None:
    HELP_TEXT = """Доступные команды:
add - добавить задачу
list - показать список задач
done - отметить задачу как выполненную
exit - выйти из программы
help - показать справку"""
    print(HELP_TEXT)

def main() -> None:

    tasks = []

    while True:
        command = input("> ").strip().lower()

        if command == "add":
            title = input("Enter task title: ")
            add_task(tasks, title)
        elif command == "list":
            print(list_tasks(tasks))
        elif command == "done":
            index = int(input("Enter task index: "))
            mark_task_done(tasks, index)
        elif command == "exit":
            print("Goodbye!")
            break
        elif command == "help":
            print_help()
        else:
            print("Unknown command, type 'help' for a list of commands.")

if __name__ == "__main__":
    main()
```

Функцию в Python определяют через `def`, затем указывают её имя и параметры в скобках. `return` завершает вызов и возвращает значение. Если выполнение дошло до конца функции без `return`, она возвращает `None`. Это специальное значение, которым обозначают отсутствие результата.

Для наглядности я использую аннотации типов. По ним IDE может подсказать, какие аргументы ожидает функция и что она возвращает.
![Pasted image 20261009011231](files/Pasted%20image%2020261009011231.png)

Стоит обсудить область видимости. У каждой функции есть свои локальные имена. Например, `local` в `a()` и `local` в `b()` — два отдельных имени. Обе функции при этом видят `shared`, определённое на уровне модуля:

```python
shared = 1  # Имя уровня модуля, доступное обеим функциям.

def a():
    local = 1
    return local + shared

def b():
    local = 2
    return local + shared
```

Посмотрим на изменяемые и неизменяемые объекты. При вызове функции её параметр связывается с тем же объектом, который мы передали. В `add_task` метод `append()` изменяет общий список, поэтому результат виден и в `main`. Числа `int` неизменяемы. Если параметр `number` связан с целым числом, операция `number += 1` связывает локальное имя с результатом сложения. Имя в вызывающем коде по-прежнему связано с прежним числом. `float`, `bool` и `str` тоже относятся к неизменяемым типам.

Обратите внимание, что чтение команд и вывод остаются на стороне интерфейса. `print_help()` тоже относится к интерфейсу. Функции для работы с задачами добавляют и обновляют данные, а `list_tasks()` возвращает текст для вывода.

Мы разделили программу на функции. Теперь разделим её на модули по смыслу. В каталоге `src/it_taskagent/` создадим `cli.py` для интерфейса и `tasks.py` для работы с задачами. Список задач перенесём на уровень модуля `tasks`, чтобы его больше не приходилось передавать в каждую функцию. Справка относится к интерфейсу, поэтому её текст оставим в `cli.py`.

Чтобы вызвать функции из `tasks.py`, можно написать абсолютный импорт `from it_taskagent.tasks import add_task` или относительный `from .tasks import add_task`. Одна точка обозначает текущий пакет, две — родительский. Точка входа в `task_agent.py` теперь будет вызывать интерфейс.

```python
tasks = []

def add_task(title: str) -> None:
    tasks.append({
        "title": title,
        "done": False
    })

def list_tasks() -> str:
    output = ""
    for i, task in enumerate(tasks):
        output += f"{i}. [{'X' if task['done'] else ' '}] {task['title']}\n"
    return output

def mark_task_done(index: int) -> None:
    tasks[index]["done"] = True

```

## Линтеры, форматтеры и зависимости

Смотрите, программирование — штука сложная. Нужно держать в голове довольно много информации:
- Как устроено приложение.
- Как взаимодействуют его части.
- Какие возможности и ограничения есть у выбранных инструментов.
- Какие абстракции уже используются в коде.

Чтобы упростить себе жизнь, разработчики договариваются об ограничениях. Например, аннотации типов помогают анализатору заметить вызов функции с неподходящим аргументом ещё до запуска программы.

Есть и соглашения о том, как оформлять код. В Python для этого есть [PEP 8](https://peps.python.org/pep-0008/). В нём описано, например, как использовать отступы и пробелы и как группировать импорты.

Когда код оформлен единообразно, его проще читать. Чтобы не держать все правила в голове, придумали линтеры и форматтеры.

Линтер анализирует исходный код без запуска приложения. Он ищет потенциальные ошибки и проверяет соблюдение выбранных правил.

Форматтер автоматически оформляет код. Для обеих задач возьмём Ruff. Установим его как зависимость для разработки командой `uv add --dev ruff`.

Выполним `uv run ruff format .`. Точка означает текущий каталог. Ruff найдёт в нём подходящие файлы и переформатирует их.

```text
$ uv run ruff format .
4 files reformatted, 1 file left unchanged
```

Ruff мог поправить пробелы, пустые строки и другие детали оформления. Изменения можно посмотреть в Git.
![Pasted image 20261009015634](files/Pasted%20image%2020261009015634.png)

Теперь давайте воспользуемся линтером:

```text
$ uv run ruff check .

 --> src/it_taskagent/task_agent.py:1:18
```

Ruff нашёл импорт `rich.print`, который остался в `task_agent.py` после переноса интерфейса. Код `F401` обозначает неиспользуемый импорт. У вас номера строк и вид сообщения могут отличаться.

## Исключения и обработка ошибок

Давайте запустим программу, вызовем `done` и введём индекс `0`, пока список задач пуст:

```text
$ uv run it-taskagent
> done
Enter task index: 0
Traceback (most recent call last):
  File "it-taskagent", line 10, in <module>
    sys.exit(main())
             ~~~~^^
  File "task_agent.py", line 5, in main
    cli()
    ~~~^^
  File "cli.py", line 16, in cli
    mark_task_done(index)
    ~~~~~~~~~~~~~~^^^^^^^
  File "tasks.py", line 16, in mark_task_done
    tasks[index]["done"] = True
    ~~~~~^^^^^^^
IndexError: list index out of range
```

Программа завершилась и вывела traceback — цепочку вызовов, которая показывает, где возникло исключение. `IndexError` означает, что элемента с индексом `0` в пустом списке нет. Если вместо числа ввести текст, получим другой результат:

```text
$ uv run it-taskagent
> done
Enter task index: Привет!
Traceback (most recent call last):
  File "it-taskagent", line 10, in <module>
    sys.exit(main())
             ~~~~^^
  File "task_agent.py", line 5, in main
    cli()
    ~~~^^
  File "cli.py", line 15, in cli
    index = int(input("Enter task index: "))
ValueError: invalid literal for int() with base 10: 'Привет!'
```

Функция `int()` не может преобразовать строку «Привет!» в целое число и сообщает об этом исключением `ValueError`. Чтобы после ошибки можно было продолжить работу, обработаем оба исключения через `try…except`.

Если в блоке `try` возникает исключение, Python ищет подходящий обработчик `except`. Голый `except` перехватит и ошибки ввода, и, например, прерывание программы через `Ctrl+C` (`KeyboardInterrupt`). А если в обработчике стоит только `pass`, пользователь даже не узнает, почему команда не сработала. Ограничимся ожидаемыми исключениями и для каждого выведем своё сообщение.

Заменим ветку `done` в `cli.py`:

```python
        elif command == "done":
            try:
                index = int(input("Enter task index: "))
                mark_task_done(index)
            except ValueError:
                rich_print("[bold red]Error:[/bold red] Invalid input. Please try again.")
            except IndexError:
                rich_print(
                    "[bold red]Error:[/bold red] Task index out of range. Please try again."
                )
```

В Python индекс `-1` выбирает последний элемент. В нашем интерфейсе пользователь выбирает номер из списка, а номера начинаются с нуля. Поэтому в `tasks.py` явно отклоним отрицательные номера. Слишком большой индекс по-прежнему вызовет `IndexError` при обращении к списку.

```python
def mark_task_done(index: int) -> None:
    if index < 0:
        raise IndexError("Task index must be non-negative")
    tasks[index]["done"] = True
```

Инструкция `raise` явно вызывает исключение. Здесь оно попадёт в тот же обработчик, что и ошибка при обращении к отсутствующему элементу. Проверим, что после обеих ошибок программа продолжает принимать команды:

```text
$ uv run it-taskagent
> done
Enter task index: 0
Error: Task index out of range. Please try again.
> done
Enter task index: Hello!
Error: Invalid input. Please try again.
> exit
Goodbye!
```

Давайте закоммитим изменения с сообщением `Добавил обработку ошибок`.
