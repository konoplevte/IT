# Лабораторная работа № 1. Репозиторий ИИ-агента

## Задание

Создать личный репозиторий на GitLab или GitHub для разработки ИИ-агента.

Порядок выполнения:

1. Выбрать назначение агента и язык программирования.
2. Создать репозиторий с основной веткой `main`.
3. Создать от `main` ветку `task1`.
4. В ветке `task1` заполнить файл `README.md` в корне репозитория. Указать:
   - название проекта;
   - назначение агента;
   - выбранный язык программирования;
   - не менее трёх планируемых возможностей;
   - два разных запроса пользователя и ожидаемые результаты.
5. Оформить README с помощью Markdown: использовать заголовки `#` и `##`, полужирное выделение `**текст**`, список и обратные кавычки для технических имён.
6. Сохранить изменения минимум в двух содержательных коммитах с понятными сообщениями. Например, отдельно зафиксировать описание проекта и сценарии использования.
7. Отправить ветку на платформу и открыть MR в GitLab или PR в GitHub **из `task1` в `main`**. Запрос должен содержать осмысленно выполненную работу, а не пустые файлы или незаполненный шаблон. В описании кратко перечислить выполненное.
8. Предоставить преподавателю доступ к репозиторию и назначить его reviewer. Для каждого нового MR или PR на обеих платформах отправить отдельное письмо со ссылкой на почту. Тема письма: `ИТ — ЛР 1 — ФИО — группа`.

## Правила и ограничения

- Работа выполняется индивидуально. Созданный репозиторий используется в следующих лабораторных работах.
- В этой работе требуется только описание проекта. Реализация агента и подключение LLM не требуются. В README описываются планируемые возможности.
- Допускается любой язык программирования. Примеры лекций на Python потребуется самостоятельно адаптировать к выбранному языку.
- Начальный коммит в `main` не учитывается при оценивании коммитов в `task1`. Пустые коммиты и сообщения вроде `123` или `update` не учитываются как осмысленные.
- **Сливать MR или PR до одобрения преподавателя запрещено.** Исправления отправляются новыми коммитами в ту же ветку `task1`.
- **Без отдельного письма со ссылкой MR или PR не рассматривается.** Для новых коммитов в уже отправленном запросе повторное письмо не требуется.
- В GitLab преподаватель добавляется с ролью минимум `Developer`, в GitHub — как минимум collaborator.
- Допуск к защите предоставляется **после одобрения (approve) работы в репозитории преподавателем через MR или PR**.
- **Защита обязательна: без неё лабораторная работа не считается сданной.** Для успешной защиты необходимо правильно ответить хотя бы на один из трёх заданных вопросов. При отсутствии правильных ответов требуется повторная защита.
- Повторная защита, в том числе для повышения балла, допускается на лабораторных занятиях до конца семестра. Учитывается лучший результат защиты, максимум — 3 балла.

### Срок сдачи

На выполнение отводится **две недели с момента выдачи задания**. Точную дату и время окончания срока сообщает преподаватель.

До окончания срока необходимо отправить выполненную работу, открыть содержательный MR или PR, предоставить доступ и отправить ссылку на почту преподавателя. Пустой запрос не считается сдачей.

Дата сдачи определяется по **наиболее позднему времени** из четырёх событий для запроса, по которому сдаётся работа:

- отправка последнего коммита сдаваемой работы на платформу;
- создание MR или PR;
- предоставление преподавателю доступа к репозиторию;
- отправка письма со ссылкой на этот запрос.

Учитывается время отправки коммитов на платформу, а не локальная дата их создания. **Любые доработки, включая исправления по замечаниям преподавателя, обновляют дату сдачи.** Если они отправлены после срока, доступный максимум снижается. Открытие пустого запроса в пределах срока не сохраняет первоначальную дату сдачи. Время проверки, одобрения и защиты в расчёт просрочки не входит.

За каждую начавшуюся неделю просрочки максимум снижается на **10% от исходного максимума**, но не ниже **60%**:

| Просрочка | Максимум |
| --- | --- |
| Нет | 20 баллов |
| До 7 суток включительно | 18 баллов |
| Более 7, до 14 суток включительно | 16 баллов |
| Более 14, до 21 суток включительно | 14 баллов |
| Более 21 суток | 12 баллов |

Итоговый балл — сумма баллов за итоговую версию работы и защиту, ограниченная максимумом с учётом просрочки. Например, работа отправлена вовремя, но исправления отправлены через 3 суток после срока: максимум составит 18 баллов. При результате 19 баллов итог будет 18, при результате 15 — 15.

## Критерии оценивания

Максимум — **20 баллов: 17 за работу и 3 за защиту** до учёта просрочки. Оценивается итоговая версия работы после исправлений. Каждый критерий оценивается отдельно; за невыполненный критерий — 0 баллов. Доработки могут повысить баллы по критериям, но обновляют дату сдачи.

| № | Критерий | Баллы |
| --- | --- | --- |
| 1 | Репозиторий доступен преподавателю для просмотра файлов и истории | 1 |
| 2 | Ветка `task1` опубликована и содержит изменения относительно `main` | 1 |
| 3 | В корне `task1` есть непустой `README.md` с названием проекта | 1 |
| 4 | Понятно описано назначение агента | 1 |
| 5 | Указан язык программирования | 1 |
| 6 | Описаны конкретные планируемые возможности: три и более — 2 балла, одна или две — 1 балл | 2 |
| 7 | Приведены два разных запроса с ожидаемыми результатами, соответствующими возможностям: по 1 баллу за каждый | 2 |
| 8 | Корректно используются заголовки `#` и `##` | 1 |
| 9 | Осмысленно используется полужирное выделение `**текст**` | 1 |
| 10 | Корректно используется список Markdown | 1 |
| 11 | Для технического имени используются обратные кавычки | 1 |
| 12 | В `task1` есть содержательные коммиты с соответствующими изменениям сообщениями: по 1 баллу за каждый, максимум 2 | 2 |
| 13 | Содержательный MR или PR направлен из `task1` в `main`, содержит описание выполненного, передан на проверку и не слит до одобрения | 1 |
| 14 | Ссылка на MR или PR отправлена отдельным письмом; тема содержит номер работы, ФИО и группу | 1 |

Разметка должна корректно отображаться на платформе. Пустые разделы и незаполненные шаблоны не засчитываются.

## Вопросы для защиты

После одобрения работы преподавателем на защите задаются **три вопроса из списка**. За каждый правильный ответ с объяснением начисляется **1 балл**. Для сдачи работы требуется хотя бы один правильный ответ. Ответы необходимо связывать с выполненной работой и при необходимости показывать команды, файлы или историю репозитория. Письменные ответы в README не требуются.

1. Чем Git отличается от GitLab и GitHub?
2. Что такое репозиторий и рабочее дерево? Для чего нужен каталог `.git`?
3. Что такое коммит? Какие изменения фиксирует один из коммитов выполненной работы?
4. Что такое индекс? Что произойдёт, если после `git add README.md` изменить файл и выполнить `git commit` без повторного `git add`?
5. Чем отличаются `git status`, `git diff` и `git diff --staged`?
6. Что такое ветка? Для чего используется `task1` и какая команда создаёт её и переключает на неё?
7. Чем отличаются `git clone`, `git fetch`, `git pull` и `git push`? Отправляет ли `git push` незакоммиченные изменения?
8. Что такое MR или PR? Какая ветка в этой работе исходная, какая целевая и что происходит при слиянии?
9. Для чего нужен `.gitignore`? Прекратит ли он отслеживание уже закоммиченного файла?
10. Что такое `origin`? Как проверить адрес удалённого репозитория и отправить в него ветку `task1`?
